# Accessibility: Phase 1 record

Target: WCAG 2.1 AA for the respondent experience and the admin app.

## Automated checks (done)

`e2e/tests/a11y.spec.ts` runs axe-core (WCAG 2.0/2.1 A and AA rules) on:

- a respondent survey containing every Phase 1 question type, in its normal state and with validation errors showing
- the admin login page, the survey list and the builder

Result: **no serious or critical violations.** The check found one real bug, Likert scale radios without an
accessible name, which is fixed.

The same spec checks keyboard operation of the respondent page: arrow keys within radio groups, Space on checkboxes,
select menus, and Next. The builder's keyboard reordering (Move up/down, Move to page) was checked in the browser.

Automated tools catch roughly a third of accessibility problems, so the manual pass below is still required.
